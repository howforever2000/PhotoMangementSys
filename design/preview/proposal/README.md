# 视觉优化方案 · 「去卡片化」· 从卡片套件到排印式界面

> 目标（用户原话）：**简约 · 有信息 · 高级 · 直观**；
> 内容卡片有**错落感**但排列**整齐有序**；文字与信息**自然嵌入背景**；
> 各大组件功能**相互独立**（相册管理的搜索只做关键词检索）。
>
> 效果图：`design/preview/proposal/mock-*.png`（1440×900 @2x，可直接打开对照）
> 可复现：`node design/preview/proposal/shoot.cjs`

---

## 零、一句话结论

现状的问题**不是「卡片不够精致」，而是「所有东西都被卡片包住了」**。
一屏里只要出现 2 类以上的容器（玻璃板 / 卡片 / 药丸 / 分段控件），
它们就会互相争夺"我是一个独立区块"这件事，读者失去了唯一的层级通道 ——
于是"有信息"变成"有很多框"。

正确方向是把容器**减到零**（只剩两处真实的物理边界：照片封面本身、输入框），
层级改由**字号 / 字重 / 文字色三档 / 发丝线**建立。

## 一、问题诊断（按你截图里看到的顺序，逐条对到代码）

### 1. 数据带：一行装不完，且「读数」与「容器」重复表达同一件事

**看到的现象**

- 地点页有 9 块读数板：第一行 4 块、第二行 4 块、第三行**只剩 1 块**孤零零挂在左边
- 相册管理 5 块；时间线 5 块 —— 每页都是"一排同尺寸灰板"
- 每块板里都有一个 30px 粗字重数字 + 一条金色进度条

**代码成因**（`src/components/ui/StatBand.vue`）

```css
.u-stat {
  flex: 1 1 0;          /* 等分 → 9 块就是 9 等分，装不下就换行 */
  min-width: 132px;     /* 132×9 + 8×10 = 1268px > 内容宽 → 必然折行 */
  max-width: 320px;
  padding: 13px 15px 14px;
  border-radius: var(--panel-glass-radius);   /* 每块都是玻璃板 */
  background-color: var(--panel-glass-fill);
  border: 1px solid var(--panel-glass-edge);  /* 每块都有一圈亮边 */
  box-shadow: var(--panel-glass-shadow);      /* 每块都在浮 */
}
```

- **折行是算术必然**：`min-width:132px` × 9 块 > 可视宽度，`flex` 只能换行；
  换行后第二行每块被拉到 `flex:1` 的更大宽度，于是**两行的板尺寸不一致** ——
  眼睛立刻把它读成"表格第二行剩了一格"
- **金色用光了**：`--c-accent` 在全站只允许出现在"当前项 / 变化值 / 图表高亮"
  三处（`tokens.css` §2.7 自己写下的预算）。现在每块板挂一条金进度条，
  等于**一屏 9 处强调** = 没有强调
- **30px + `--fw-em`(560)**：五个数字全部加粗加大的结果，是五个都不是重点

**改法**

| 项 | 现状 | 提案 |
|---|---|---|
| 容器 | 每列一块玻璃板（填充 .20 + 亮边 + 投影） | **无容器**：文字直接落在背景上 |
| 分隔 | 板与板之间的"缝" | 一根 12px 高的 `1px` 发丝竖线 |
| 宽度 | `flex: 1 1 0` 等分（→ 折行） | **按信息量加权**（`w-1` / `w-2`），**永远一行** |
| 读数 | 30px / 字重 560 | 30px / 字重 **340**（细字重才是排印） |
| 强调 | 每块一条金进度条 | 金色只留 1 处；其余进度线用 `--fg-3` |

一屏读完的逻辑变成：**标签（这列是什么）→ 读数（多少）→ 注释（补充）**，
三行同基线，五列横着扫一眼就完。

### 2. 左筛选栏：一整块灰板 + 每一项都是一个小卡片

**看到的现象**

- 相册管理左边一整块灰色玻璃板，里面「排序 / 入库 / 年份 / 快捷」四组
- 每个选中项都有**整块圆角底色**

**代码成因**（`src/views/AlbumList.vue`）

```css
.album-side::before {          /* 整块玻璃板是伪元素画的 */
  inset: 0 -10px -10px -12px;  /* 还向外扩 10-12px */
  background-color: var(--panel-glass-fill);
  border: 1px solid var(--panel-glass-edge);
}
```

- 左栏是一块板，右栏内容区又是一片板 —— **两栏之间一条暗缝**，
  读起来是"两个抽屉并列"，不是一个页面的两栏
- `inset` 向右/下各扩 10–12px，导致左栏的实际边界比它的内容框大，
  **与右侧内容的起始线对不齐**（这也是这条左栏无论怎么调都"看着别扭"的原因）

**改法**

- **删掉左栏的玻璃板**（`.album-side::before` 整个移除）——
  它承载的是文字列表，文字自己会形成一列，不需要底板
- 选中态从"整块圆角底色"改为：**左侧 2px 竖条 + 文字提亮到主色**，
  底色只留 `--hover`（≈5% 白，几乎不可见）
- 分组标题保持 9.5px 大写 + `.15em` 字距，与数据带标签**用同一套字阶**
  （现在左右两处的分组标题是两套字号，这就是"没对齐"的隐性来源）

### 3. 相册瓦片：图注压在封面上，把照片盖掉一块

**看到的现象**

- 每一张封面上都压着一个深色胶囊（名字 + 张数），再上面一个更小的日期胶囊
- 一屏 12 张照片，每一张都被盖掉左下角约 15% 面积

**代码成因**（`src/components/AlbumCard.vue`）

```css
.tile-cap { position: absolute; left: 8px; bottom: 8px; }
.tile-cap-in {
  background: rgba(8, 10, 14, 0.52);   /* 深色胶囊 */
  padding: 3px 9px;
}
.tile-time { position: absolute; left: 8px; bottom: 44px; }  /* 再叠一个胶囊 */
```

- 胶囊方案是给 **"一屏几十块"的密排墙**设计的（那时文字必须有个底才读得出来）
- 但现在一行只有 3–5 块，**封面本身就是足够大的对比面**，
  胶囊反而变成"贴在照片上的黑色贴纸"
- 而且**两个胶囊垂直堆叠**（bottom 8 / bottom 44），在 186px 高的封面上占了 74px

**改法**

```
封面（无遮挡）
  ├─ 左下角：日期（9.5px 裸文字 + 文字阴影，不加深色块）
  └─ 右上角：未入库（9px 裸标签 + 文字阴影）
封面下方一行裸文字：  名字（13px 主色）  张数（10.5px 弱色）
```

- 封面上只留**文字**，不加任何背景块 → 照片完整可见
- 为让白字在浅色照片（雪、天空）上仍可读，封面底部加一条 **34px 高的极淡渐变**
  （最深 `rgba(0,0,0,.30)`）—— 低于这个值浅照片上白字消失，
  高于这个值就变成"压在照片上的黑带"
- 图注从"胶囊"改成"封面下方一行"：**没有底、没有框、没有描边**，
  名字与张数之间用 7px 间距连成一串

> ⚠️ 一个容易踩的细节：张数**不要** `margin-left: auto` 推到最右。
> 瓦片宽度不同，推到右边会让每一行的张数落在不同 x 位置，
> 读起来是两栏表格而不是一句描述。

### 4. 搜索：相册管理的搜索框其实在做两件事

**这不是视觉问题，是功能边界问题**（你说的"各个大组件功能应相互独立"）

**代码事实**（`src/views/AlbumList.vue`）

```ts
function onSearchInput() {
  const [albums, contents] = await Promise.all([
    invoke("search_albums", { keyword: kw }),        // ① 相册名检索
    contentStore.searchPhotoContent(kw),             // ② 全库照片内容检索
  ]);
  searchResults.value = albums;
  contentHits.value = contents;
}
```

```html
<!-- 搜索结果面板里同时渲染两组 -->
<div class="search-section-title">相册</div>
<div class="search-section-title">照片内容（{{ contentHits.length }}）</div>
```

- 相册管理的搜索框 placeholder 写的是 **"搜索相册名称…"**，
  但它同时在跑**全库照片内容检索**，结果里还会出现"照片内容"分组
- 也就是说：**相册管理里藏着一个智能搜索**，而 `/search` 页面也有一个。
  用户在任何一处都搞不清"这次搜索到底在搜什么"

**改法（功能隔离）**

| 位置 | 只做 | 出口 |
|---|---|---|
| 相册管理顶栏 / 内容区搜索框 | `search_albums`（相册名 + 分组名） | 框内右侧常驻灰字「不检索照片内容」+ 右侧一个「去智能搜索 →」文字链接 |
| 智慧相册 → 智能搜索 | `search_photo_content`（内容 / 人物 / 地点） | 独立页面，独立 scope 标签 |
| 顶栏搜索胶囊 | 全库照片（跨相册） | 胶囊里写明范围（`全库` / `仅名称`） |

**关键设计原则**：让**范围写在框里**，而不是靠用户点进去试。
搜索框里的 `scope` 后缀是个 10.5px 的灰字，成本极低，但它是"功能边界"唯一诚实的表达。

### 5. 地点页：地图占了大半屏，但 60% 是空白

**看到的现象**（第二张截图）

- 上半屏 9 块读数板（4+4+1，第二行末尾空一块）
- 下半屏一张中国地图，所有光点**挤在西南角两三个省**
- 地图上方还有一行「地图 / 卡片」分段控件 + 一句说明

**代码成因**（`src/components/LocationGallery.vue`）

- 地图容器占满剩余高度，但数据只有 24 个城市 / 7 个省 ——
  **地理分布高度集中**，剩下的省份必然是空白
- 视图切换（地图/卡片）单独占一行，而顶栏已经有「地点」tab，**两处都在做切换**
- 「占 用 存储 / 相册 / 已入库 / 人物」这类**与地点无关**的读数也被塞进来
  （从截图看，数据带里混了 25085 张 / 81.3GB / 130 个相册 / 24987 已入库 / 933 位人物）

**改法**

1. **读数只留与"地点"有关的 4 项**：地点城市 / GPS 覆盖 / 无定位 / 最大聚集。
   其余（照片总数、占用、相册数、人物数）属于"整库规模"，那是 Home 的事
2. **地图 + 右侧地点榜两栏**：把空白交给有信息的列表
   - 为什么不铺卡片墙：24 个城市铺卡片要 6 行 × 180px ≈ 1080px，
     而且每张卡 85% 面积是同一类封面，信息密度极低；
     榜单一行 30px，24 行 = 720px，**密度高 4 倍**，
     而且「排名」这个信息卡片根本表达不出来
3. **视图切换压到地图右上角**（分段控件不再单独占一行），
   说明文字并进地图左下角的读数行
4. 地图本身：轮廓只留一根极淡的线（`rgba(255,255,255,.12)`），
   **空省不画省界** —— 只在有数据的区域画边界，整张图更干净

### 6. 时间线：页内标题重复 + 原生 `<select>` 盖住数据带

**看到的现象**（第三张截图）

- 顶栏已有「时间线」tab，下面又一行 22px 的 **「照片时间线」** 大标题
- 再下面一行「共 24987 张」+ 年份下拉，**单独占一行**
- 然后才是 5 块数据带
- 那个年份下拉是一个**白底黑框的原生 `<select>`**，正压在第一块数据带上

**代码成因**（`src/views/Timeline.vue`）

```html
<header class="tl-header"><h1 class="tl-title">照片时间线</h1></header>
<div class="tl-toolbar">共 {{ total }} 张  <select v-model="yearFilter" class="tl-year-select">…</select></div>
<StatBand :items="timelineStats" class="tl-stats" />
```

- 标题 → 工具条 → 数据带 = **三行 200px** 才看到第一张照片
- 白底下拉：`<select>` 的 `option` 列表由操作系统绘制，**CSS 控制不了**；
  深色主题下必然出白底（这是平台行为，不是样式没写）
  （这个类名碰撞在 `BUG-2026-1024-*` 里已经修过一次，但**白底 option 无解**）
- 更根本的问题：**时间线的正文只有「年 → 月 → N 张」三层文字**，
  一个照片应用的时间线**看不到照片**，这是最大的信息浪费

**改法**

1. 标题降到 17px（"小标题"档，不再是 hero），与「共 N 张」「年份筛选」**合并成一行**
2. 年份筛选换成**自绘控件**（同按钮规格），彻底避开原生 select 的白底
3. 数据带从 5 列降到 4 列：「无拍摄时间」与「地点覆盖」这类**诊断读数**
   在任何一年都读同一个值，不该各占一列 —— 合并进注释
4. **月行右侧加缩略图带**（58×40 / 张，一行 24 张，超出裁切）：
   一屏从"3 行文字"变成"6 个月的照片本身"
5. 年组头右端挂**月度柱阵**（12 根 4px 柱），不再单开第 6 块读数

### 7. 全局：三套材质同时在场

| 材质 | 令牌 | 现在被用在哪 |
|---|---|---|
| 墙板玻璃 | `--panel-glass-*` | 数据带、左栏、入口卡、扫描面板、瓦片图注 |
| 浮层玻璃 | `--glass-*` | 顶栏、搜索胶囊、弹窗、右键菜单 |
| 纸片 | `--slip-*` | 组级小面板 |
| 组件色调玻璃 | `cardStyle`（内联） | 相册 card 变体、Home 用户区… |

README 里写了"三种玻璃各司其职"，但**实际有第四种**（`cardStyle` 内联路径）。
四套材质的结果：同一屏里，顶栏、数据带、左栏、瓦片图注的**透光度与模糊度都不同**，
眼睛读到的是"四层不同的玻璃叠在一起"。

**改法**

- **容器归零**：数据带、左栏、组头、图注 → 全部无底
- 只保留两处真实容器：
  - **输入框 / 搜索框**（必须有边界，否则不知道能打字）
  - **弹窗 / 菜单**（必须盖住内容）
- `--panel-glass-*` 从"通用面板"缩到"仅扫描面板 / 空态卡"这类**独立功能区**
- 结果：一屏最多 **1 类**容器（顶栏那一条），其余全是文字与照片

## 二、统一规则（改完之后所有页面都按这个走）

### 2.1 字阶（只 5 档，不留第 6 档）

| 用途 | 字号 | 字重 | 色 |
|---|---|---|---|
| 微标签（列头 / 分组头） | 9.5px / `.15em` / uppercase | 600 | `--fg-3` |
| 元信息（张数 / 单位 / 日期） | 10.5–11px | 400–500 | `--fg-3` |
| 正文 / 导航 / 图注名 | 12.5–13px | 500–600 | `--fg-2` / `--fg` |
| 区块标题（年份 / 页内标题） | 17–22px | 620 | `--fg` |
| 读数 | 30px | **340** | `--fg` |

> 读数用细字重是本方案最反直觉、也最关键的一条。
> 大字号 + 粗字重 = PPT 图表；大字号 + 细字重 = 排印。

### 2.2 只有三档文字色

```
--fg    #f0eef3            主：读数、标题、当前项、图注名
--fg-2  rgba(...,0.60)     次：标签、导航、注释
--fg-3  rgba(...,0.38)     弱：单位、计数、分组头
--rule  rgba(255,255,255,0.085)   发丝线（非文字）
```

**不允许有第四档**。现在的问题之一就是同一个"次要文字"有时用 `--c-fg-2`、
有时用 `--color-text-2`、有时用 `opacity: .7` —— 三种灰互相差 5%，看着就是"脏"。

### 2.3 金色预算：一屏最多 2 处

| 允许 | 不允许 |
|---|---|
| 当前选中项（tab 下划线 / 左栏竖条） | 每个读数一块金进度条 |
| 主行动按钮（新建相册） | 每个瓦片的边框 |
| 地图上"第一名"的光点 | 所有图注的强调 |

### 2.4 间距与留白

```
页面左右留白   var(--gutter) = 48px（现状 52px，略收）
数据带上下     20px / 16px
区块之间       26px
行内元素       6–10px
```

## 四、与「错落感」的关系（这是你特别提的一点）

错落感**不能靠随机尺寸**（随机布局每次刷新都不一样，用户找不到上次那个相册），
只能靠**可预期的周期**。现状的周期是「每 5 块一张 1.5 倍宽幅」，
这个思路是对的，保留。但要让错落"整齐有序"，还需要两条：

1. **一行内严格等高**（现状已做到，`justifiedRows.ts` 的行高统一）
2. **图注基线必须对齐**：图注从胶囊移到封面下方后，
   `.cap` 的 `line-height` 要固定（`18px`），否则不同字数的名字会让下一行的封面错位

效果图里第 2 行的「人像」是宽幅瓦片 —— 错落来自"一块更宽"，
而每一行仍然严格铺满、严格等高。这就是"错落但有序"。
