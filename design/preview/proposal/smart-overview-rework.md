> 只重排、不加功能、不动数据源。两套方案都只用现有组件（`WidgetGrid` / `UiWidget` /
> `BarsCore` / `CoversCore` / `RankBarsCore` / `MemoryCore`）和现有快照字段。

## 一、现状的问题（对着 `overview-current.png` 指认）

骨架是 6 行：照片库 7×2 + 今年月度 5×2 / 相册 4×2 + 人物 4×2 + 地点 4×2 /
最近导入 8×2 + 那年今日 4×2。骨架没错，问题在**每个格子里的内容没有用满自己的格子**。

1. **首屏 7×2 的右半边是空的。**
   24,980 与「137.2 GB · 12 个相册」挤在左上角，已入库进度贴在最底部，
   中间 120px 什么都没有，而这 7 列里其实只有左侧 5 列有字。

2. **12 根月度柱子没有月份刻度。**
   标题只写「2026 · 当月 416 张」，读者无法把某根柱子定位到某个月——
   这张图只能看出"形状"，看不出"几月"。

3. **三块 4 列面板被同一套宽度压扁。**
   相册只能排 1 大 + 2 小（3 张），人物只有一行 6 个 46px 头像、占不到面板 1/3 高度。
   它们的**内容形态完全不同，却被迫同宽同高**。

4. **最近导入 8×2 只用了一条细带。**
   6 张缩略图横排、每张只有 ~190×60，面板上下各留一大条空白；
   而"最近导入"其实是这一页最该被点的地方。

5. **那年今日与三个统计入口同权重。**（这条在 A 里不构成问题，见下）

## 二、方案 A（推荐）：保骨架，补三处短板

> 第一版曾把首行压成一条 1 行的"仪表带"，实测过紧（首屏只剩 116px 高），
> 这一版**保留原来的两行高度**，只把空着的地方填上。

```
┌─────────────────────────────────┬───────────────────────────────────┐
│ 照片库 7×2                       │ 今年月度 5×2                       │
│  24,980 张 · 137.2 GB · 2015–26  │   12 根柱 + 1…12 月份刻度          │
│  ─────────────────────────────   │   全年 / 月均 脚注                 │
│  已入库 73.7% ▓▓▓░░ │ 语义索引 93.5% │                                 │
├─────────────────┬───────────────┼───────────────────────────────────┤
│ 相册 4          │ 人物 4        │ 地点 4                             │
│ 1 大 + 2 小      │ 4×2 头像+姓名 │ Top5 横条                          │
├─────────────────┴───────────────┼───────────────────────────────────┤
│ 最近导入 8（3×2 网格 + 相册/日期） │ 那年今日 4（大封面，保持现状）      │
└─────────────────────────────────┴───────────────────────────────────┘
```

### 逐块改动（只 3 处，其余原样）

**① 照片库（7×2）：把下半块铺满**
大数字与元信息行保持原位；下半部分成两栏、用一根发丝竖线分开：
`已入库 73.7%` + 金色占比线 + `18,420 / 24,980 张` ｜ `语义索引 93.5%` +
`17,230 张已建索引 · 9 个分类` + `118 张属其他模型档`。
信息一条没少，但 7 列的宽度第一次被用满，中间那块 120px 的空白消失。

**② 今年月度（5×2）：补月份刻度**
`BarsCore` 本来就有 `labels`，现状没用。补上 `1…12`，脚注补「全年 5,095 张 · 月均 510 张」。
柱子宽度、金色当月柱都不动。

**③ 人物（4×2）：一行头像 → 4×2「头像 + 姓名 + 张数」**
现状只有头像、认不出人，而且一行 46px 头像占不到面板 1/3 高度。
这是本方案唯一的**新增标记结构**（`.ov-faces`，仍写在 `OverviewPane.vue` 里，不改 `FacesCore`）。

**④ 最近导入（8×2）：一条细带 → 3×2 网格**
单张从 ~190×60 变成 ~460×90，每张右下角叠「相册名 · 日期」。面板高度不变，内容撑满。

**⑤ 相册 / 地点 / 那年今日：不动**
相册仍是 1 大 2 小 + 总量脚注；地点仍是 Top5；那年今日仍是 4×2 大封面——
它是这一页唯一的"情感钩子"，保持原有重量。

### 效果

- 页面总高与现状基本一致（内容底 826 → 845px @1600），**不新增滚动**。
- 首屏右半边不再空；月度第一次有了刻度；最近导入第一次"看得清"。
- 板数不变（5 块玻璃板 + 2 块裸），金色仍只有两处（入库占比线、当月柱）。

## 三、方案 B（备选）：年份主轴

把"今年月度"升级成**整库时间分布**：12 根柱子 = 2015–2026，柱下标年份，当年高亮；
左边压大数字 + 已入库线。下面三块是相册 5 / 人物 3 / 地点 4，底部是最近导入 8（细带）+ 那年今日 4。

适合"我更想知道这些年拍了多少"的人；代价是**今年内的节奏被抹平**（月度信息消失），
且底部两块又回到"同重量"的老问题。所以推荐 A。

> 如果两个都想要：可以在这块里做双行柱阵（年份在上、月份在下），
> 代价是这一块要从 2 行长到 3 行。

## 四、落地清单（选 A 时）

只动一个文件：`src/components/OverviewPane.vue`

1. 模板：照片库块的下半改成 `.ov-split`（两栏，发丝线）；`BarsCore` 传 `:labels`；
   人物块换 `.ov-faces` 4×2；最近导入换 `.ov-recent` 3×2（保留 `thumbQueue` 取图逻辑）。
   其余 `span/rows` 与文案原样。
2. 样式：新增 `.ov-split*` / `.ov-faces*` / `.ov-recent*` 三组；删掉 `.ov-hero-side`
   那套竖线右栏（已被 `.ov-split` 的第二栏取代）。颜色仍只用 `--w-*` / `--fg-*` / `--rule`。
3. 数据：零新增。`months` / `recent` / `persons` 都已在快照里。
4. 不改 `WidgetGrid`、`UiWidget`、任何 `*Core`。

风险点：
- 人物数 < 4 时 4 列会出现半行空位 —— 用 `Math.min(4, persons.length)` 控制列数。
- 最近导入的 3×2 在 1280 宽下单格约 380×90，仍可读（已按 1280/1600/1920 三档验证无溢出）。

## 五、验证口径

- `npm run build`（含 `vue-tsc --noEmit`）通过；`npm test` 全绿。
- 三档视口 1280×800 / 1600×1000 / 1920×1080 均无横向溢出（稿件已测：`docW === 视口宽`）。
- 页面内容底 ≤ 现状 + 30px（即改版不引入新的滚动）。
- 数字/标签不截断；收起信息、切换 tab 不受影响（本次不动脚本逻辑）。
