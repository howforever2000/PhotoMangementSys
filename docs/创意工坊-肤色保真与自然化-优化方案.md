## 三、基线实测（关键结论，均为真实数据）

在 12 张人像上跑「原图 → auto_grade(natural,0.85) → local_film(classic_neg,0.22)」，用 BiSeNet 皮肤掩码取**中位数** LCh 统计：

### 3.1 滤镜确实把肤色带偏了

| 指标 | 实测范围 | 中位 |
|---|---|---|
| 色相角偏移 Δh | **−2.4° ~ −22.4°** | 平均 **9.0°** |
| 彩度偏移 ΔC | −5.2 ~ +13.8 | — |
| 皮肤 R/G 比偏移 | +0.007 ~ **+0.356** | — |

**偏移方向是系统性的：一律把色相角往低拉（往红/暖拉）** —— 这正是「滤镜后发红、脸变红扑扑」的来源。

### 3.2 素材本身分两类（决定了方案不能一刀切）

| 类型 | 原图色相角 h | 数量 | 含义 |
|---|---|---|---|
| 户外自然光 | **49°~57°** | 4 张 | 本来就是「白黄」，需求 2 只需微调 |
| 室内/暖光 | **23°~36°** | 8 张 | 本来偏红橙，**不是滤镜的锅** |

> ⚠️ **这是方案设计的分水岭**：若把所有人一律拉到固定「白黄」色相角（如 58°），室内人像会被强行改成另一种肤色 —— 那违反需求 1（接近原图），也不自然。
> **结论：目标必须是「原图 h + 有界小偏移」，不是绝对目标值。**

### 3.3 critic 已有一次真实误报

`critic.py` 的肤色偏移阈值 `_SKIN_RG_DELTA = 0.25`。素材中 1 张实测 ΔR/G = **+0.356**，**已超过阈值** —— 即滤镜链单独作用就会触发「肤色偏移」告警。
> 新增肤色算子后，这个告警会**必然**误报（因为算子本来就在改肤色）。必须处理，见 §七。

## 四、算法方案（分两层，对应两条需求）

### 4.1 核心模型

在 **CIELAB / LCh** 空间工作（与 `autograde` 一致；§25 踩坑记录已定「饱和度类操作必须在 LCh 里做 + 必须色域回收」）。

```
锚点 h_target = h_orig(原图皮肤中位色相) + Δh     （Δh 默认 +3°，往黄）
锚点 C_target = C_orig(原图皮肤中位彩度) + ΔC     （ΔC 默认 +1.5）
```

**需求 1（接近原图）由锚点本身承载**：滤镜造成的 h 偏移被抵消，因为目标锚点来自原图。
**需求 2（白黄嫩红）由有界小偏移承载**：Δh 往黄、ΔC 微增（透亮）、颊部 a\* 额外 +1.2（嫩红）。

### 4.2 逐像素增量（不是全脸统一旋转）—— 这是「自然感」的关键

**错误做法**：把整张脸的每个像素都转到同一个 `h_target`。
→ 鼻尖偏红、耳朵偏黄、颊部偏粉的**自然差异被抹平**，脸变成一张色卡。这就是「不自然」的技术来源。

**正确做法**：逐像素**增量**旋转，保留像素间的相对结构：

```
Δh      = h_target − h_median(当前皮肤)
C_ratio = C_target / C_median(当前皮肤)
h_new   = h_pix + Δh            （C < 4 的像素不转，C≈0 时 h 是噪声）
C_new   = min(C_pix × C_ratio + ΔC, C_hard_max)
```

**实测验证（v4/v5，12 张）**：

| 指标 | 滤镜后 | 修复后 | 原素材 |
|---|---|---|---|
| Δh(相对原图) 平均 \|值\| | 9.01° | **2.73°** | — |
| **面部色相离散度 h_sd** | 13.64° | **13.59°** | 12.9~16.9° ✅ **保住** |
| Δh 中位数（方向性检查，应为正=更黄） | — | **+2.92°** | — |
| critic 误报张数 | 1 | **0** | — |
| **掩码外像素改动** | — | **0 px** | — |

> h_sd 保住（13.64 → 13.59）是「自然感」成立的**客观证据**；全脸统一转法的 h_sd 会压到 ~0。

### 4.3 白与嫩红

- **白（提亮）**：明度是影调语义，滤镜已经动过。实测**硬提 +2 会引入 40009px 通道截断**（v3 实测），必须带高光保护：只对 `L < L_safe(78)` 的像素提，权重随 L 升高线性衰减到 0。
- **嫩红**：只在**颊部**加 a\*（+1.2）。颊部定位用脸框几何近似（零新增模型依赖）；若引入 68 点可用眼角/嘴角三角，更准但多一次推理。
- **彩度软上限**：`C_hard_max = 30`，压掉「滤镜把皮肤拉得过艳」。

### 4.4 色域回收（必须做）

色相角旋转不是「缩放 C」，`autograde._chroma_headroom` 那套不能直接复用。需**新写**一个二分：固定 (L, h) 求 sRGB 内最大合法 C。
> ⚠️ v2 实测踩到：**二分上界必须是目标彩度 `newC`**，不能是 `max(newC, C)` —— 否则返回值可能 > newC，彩度没被压回目标值，且旋转后越界被 clip。正确写法 `finalC = min(newC, fit_chroma(...))`。

## 五、工程落点（新增一个算子，不改既有算子）

### 5.1 为什么是独立算子而不是改 auto_grade

`auto_grade` 的 `eval_colors` 是**逐色纯函数**（无空间运算），这是它能烘焙成 33³ LUT 的前提。肤色处理**必须**有空间信息（人脸掩码），塞进去会破坏 LUT 烘焙能力，也会污染 LUT 导出/缓存语义。

### 5.2 需要新增的通道：跨算子的「原图肤色基准」

这是唯一的架构级改动。当前 `pipeline.execute_plan` 是**纯线性**（后一步吃前一步输出），算子之间不传标量。

**方案**：新增 `skin_tone` 算子，但需要它能拿到「原图」。两条路：

| 方案 | 做法 | 代价 |
|---|---|---|
| **A（推荐）** | 在 `execute_plan` 里保留 `source`（入参原图），通过 `ctx` 或额外参数传给需要它的算子 | 改 `pipeline.execute_plan` 签名 + 算子签名（`fn(img, params, providers, ctx)` → 加一个可选位） |
| B | 新增独立算子 `skin_ref_capture`（采样原图肤色，stage 0），产出写进作业级共享状态 | 引入作业级可变状态，破坏算子纯函数性；且并行批量下状态隔离麻烦 |

> **选 A**：一次签名扩展，长期看所有「需要原图」的算子都能受益。`pipeline.execute_plan` 已经持有 `img`（原图），改动集中。

### 5.3 新算子规格（写入 `op_catalog.json`）

```jsonc
{
 "id": "skin_tone",
 "label": "肤色保真",
 "desc": "以原图肤色为基准，抵消调色/滤镜带来的偏色；再按幅度微调白黄与嫩红",
 "backend": "local",
 "stage": 3.5,              // ← 见下方「stage 陷阱」
 "module": "ai_studio.ops_local",
 "params": {
   "hue_shift":  { "type":"range", "min":-10, "max":10,  "default":3,   "step":0.5, "label":"色相偏移" },
   "chroma":     { "type":"range", "min":-6,  "max":6,   "default":1.5, "step":0.5, "label":"彩度微调" },
   "brighten":   { "type":"range", "min":0,   "max":4,   "default":1.5, "step":0.5, "label":"提亮" },
   "blush":      { "type":"range", "min":0,   "max":3,   "default":1.2, "step":0.2, "label":"嫩红" }
 },
 "requires": { "models": ["det_10g", "face_parsing_r34"] },
 "requiresBefore": ["auto_grade", "local_film", "color_transfer", "skin_smooth"]
}
```

> ⚠️ **`stage` 陷阱（必须先解决）**：`catalog.py` 校验 `requiresBefore` 指向的算子 stage **必须严格更小**，且 stage 是**整数**。
> 现有 `skin_smooth` = 3，`local_vibrance` = 5，`local_upscale` = 4 —— **stage 3.5 无处安放**：
> - 放在 3 → 不能声明 `requiresBefore: ["skin_smooth"]`
> - 放在 4 → 会与 `local_upscale` 同级，且 `local_vibrance`(5) 会在它之后跑，把刚还原的肤色又推偏
>
> **解法**：把 `skin_tone` 定为 **stage 4**，并把 `local_upscale` 从 4 挪到 5、`local_vibrance` 从 5 挪到 6，或直接让 `skin_tone` 声明 `requiresBefore` 时不含 `local_vibrance` 并在配方里把它排到 `local_vibrance` 之前。**这一项需要实改 `op_catalog.json` 的 stage 编号，是本方案唯一的破坏性改动。**

### 5.4 配方改动

「人像」配方（`recipes.json`）插入：
```
auto_grade → local_film → face_reshape → skin_smooth → skin_tone → local_vibrance
```
其余三条配方（natural / clear / film）**不加** —— 它们不保证有人像，加了只是白跑一次检测+分割（实测 ~80ms/张）。

### 5.5 参数白名单

`recipecatalog.py:TUNABLE_PARAMS` 必须补一行，否则工作台的样片微调传不进后端：
```python
"skin_tone": frozenset({"hue_shift", "chroma", "brighten", "blush"}),
```

## 七、必须处理的三个陷阱

### 陷阱 1：critic 的肤色告警必然误报

`critic.py:111` 用 `|skinRG 变化| > 0.25` 判「肤色偏移」。肤色算子**本来就在改肤色** → 每张人像都报。

**处理**：`critic.compare` 增加一个「本次是否有意调肤色」的豁免位（如 `expect_skin_shift=True`），由 `recipe.py` 的 `_critic` 调用点根据 plan 是否含 `skin_tone` 传入。
> ⚠️ 不要用「放宽阈值」糊过去 —— 那会让真偏色也检测不到了（§17 踩坑记录：阈值过松漏报、过紧变噪音源，两个方向都坏）。

### 陷阱 2：stage 是整数，且要求前置严格更小

见 §5.3。这是**唯一**会破坏既有配方的改动，必须先在 `op_catalog.json` 里理顺编号，再写算子。

### 陷阱 3：与「不做清单」的边界

`workshop-positioning.md` 的不做清单含「精修级人像控制」，但 2026-11-17 修订明确放开了「配方级量」微调（瘦脸/大眼/磨皮/保留质感/调色力度）。
本方案是**配方级量**（一个滑条族，非色轮/曲线/画笔），**不越界**，但需在该文件补一条修订记录，明确「肤色保真属于配方级微调，不是精修级人像控制」。

## 十二、第二期：美化加档 + 逐脸性别侧重 + 锚点复用（FEAT-209，2026-11-22）

用户反馈：①贴近原图但「不够白、不够嫩红」；②希望按性别分侧重，性别可用发长判断（到脖颈=女生）；③把肤色步的性能优化掉。

### 12.1 效果：白与嫩红的机制根因

| 项 | 旧实现 | 现在 | 实测（3 张 12MP 人像 × 2 脸） |
|---|---|---|---|
| 提亮 | `w=(78−L)/38`，中间调 L≈59 只拿 0.5 | `L≤70` 全量、`70~78` 收口、`≥78` 不动 | 默认 1.5→2.2，中间调 +0.75 → **+1.9 L\*** |
| 嫩红 | 颊部矩形硬边，强嫩红留直线色块 | 颊部掩码羽化（短边 4.5%） | 默认 1.2→1.8，边界 a\* 阶跃 3.5 → **<0.6** |
| 上限 | brighten 4.0 把中间调锁在 +2.0 | 曲线放开后 4.0 更有效 | — |

### 12.2 性别侧重：只改偏置层，不改锚点层

- `skintone.for_gender(p, long_hair)`：长发用用户档位（更白更嫩红）；其余 `hue_shift/chroma/blush=0`、`brighten×0.4`。
- 「还原原肤色」由锚点差算出，两档都执行 → 男性档 = 还原 + 白一点（实测 L +0.7~0.8、颊部 a\* 回原图），女性档 L +1.7~1.9、颊部 a\* +1.4~1.5。
- 发长判定在 `hairlength.py`（纯函数，零新增模型）：BiSeNet 的 `hair` 类 + 检测框几何，**双条件**（底边占比 + 脸侧占比）避免兜帽误判；单脸 <1ms。
- **已知局限**：盘发/扎高马尾/贴头皮短发判成男性档。毕业照样本（18 脸全男性）误判 0/18；婚礼样本女性召回约 2/8（散发/齐肩发命中）。失败模式刻意宽松。

### 12.3 性能：锚点复用

- 几何一致且同尺寸时，原图锚点直接用本图掩码；形变（局部液化）不再算「脏」，只有整幅重绘/缩放（`mark_geometry_changed`）才回退重分析。
- 依据：slim=0.8 强形变下复用误差 Δh ≤0.52°/ΔC ≤0.45/Δcheek_a ≤0.54（slim=0.3 时 ≤0.21）。
- 实测：`skin_tone` 步 **152~211ms**（旧 569~657ms，省 388~492ms / 65~75%）。
- 顺带修掉：`src_arr` 与掩码身份耦合的静默退化；强形变下按序号 zip 配错脸（复用掩码后不再配对）；`local_beauty` 重复的 detect→parse→smooth 实现。
