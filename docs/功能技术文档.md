# 本地相册管理系统（PhotoManagementSys）功能技术文档

> 版本：v0.3.1 ｜ 更新日期：2026-09-19
> 定位：Windows 桌面端本地照片管理应用——相册组织、照片浏览、AI 内容检索（语义/文本/色调/人物/地点），全程本地运行、不依赖云端。

---

## 一、系统概览

### 1.1 技术栈

| 层 | 技术 | 说明 |
|----|------|------|
| 前端 | Vue 3 + TypeScript + Pinia + Vue Router + Vite | SPA，15 个视图页面 |
| 桌面壳 | Tauri 2.x（Rust） | WebView2 承载前端，Rust 侧提供 100+ 个 `#[tauri::command]` |
| 数据库 | SQLite（rusqlite） | 单连接 + WAL 模式，存放于用户数据目录 |
| AI 服务 | Python sidecar（`python-studio/server.py`） | HTTP 服务，承载 CLIP 向量、人物识别（VCR）等模型推理 |
| 图像处理 | Rust `image` + `jpeg-decoder` | 缩略图生成（本地、零外部依赖） |

### 1.2 进程与数据流架构

```
┌─────────────────────────────────────────────┐
│ WebView2（Vue 3 前端）                       │
│   invoke("command", args) ⇄ JSON 序列化     │
└──────────────────┬──────────────────────────┘
                   │ Tauri IPC
┌──────────────────▼──────────────────────────┐
│ Rust 主进程（src-tauri）                     │
│  ├─ 命令层：auth/album/photos/content/...   │
│  ├─ 领域层：thumbnail/photo_scan/tone/...   │
│  ├─ 数据层：db/*（SQLite WAL）              │
│  └─ logger.rs（AOP 日志 + 监控心跳）         │
└───────┬─────────────────────┬───────────────┘
        │ 本地磁盘 IO          │ HTTP (127.0.0.1 随机端口)
┌───────▼────────┐   ┌────────▼────────────────┐
│ 照片文件系统     │   │ Python sidecar 进程      │
│ (原图/缩略图缓存)│   │ CLIP / VCR 人脸模型推理  │
└────────────────┘   └─────────────────────────┘
```

### 1.3 关键目录

| 路径 | 内容 |
|------|------|
| `src/` | 前端源码（views / stores / components / router / utils） |
| `src-tauri/src/` | Rust 后端（按领域拆分的模块化结构） |
| `python-studio/` | Python 推理服务（CLIP、人物识别模型） |
| `%APPDATA%/com.haoyuan.photo-management-sys/` | 运行时数据：数据库、缩略图缓存、会话 token、日志 |
| `%APPDATA%/.../thumbs/` | 缩略图缓存（`grid/` 网格子目录 + 封面子目录） |
| `%APPDATA%/.../logs/app.log` | 运行日志（分级 + 轮转） |

### 1.4 全局状态（Rust 侧）

- `AppState(Mutex<Database>)`：单一 SQLite 连接的全局锁。已开 `journal_mode=WAL` + `synchronous=NORMAL`，读写并发友好。所有命令短锁访问，重 IO 一律在锁外/`spawn_blocking` 中进行。
- `SessionState(Mutex<Option<i64>>)`：当前登录用户 id，`require_user()` 统一做登录校验，实现**多用户数据隔离**（所有查询带 `user_id` 过滤）。
- `ScanState`：全局扫描状态（进度事件用）。

### 1.5 日志与运行监控（logger.rs）

- AOP 风格：`log_call!` 宏在每个命令入口记录 START，`log_call_end_with` 记录耗时与结果。
- 四级过滤 `DEBUG/INFO/WARN/ERROR`，`PMS_LOG_LEVEL` 环境变量控制（默认 info，降噪一半；debug 可见每条命令明细）。
- 慢调用自动升级：命令耗时 ≥1s → WARN + `SLOW` 标记；返回 `ERR/FAILED` → ERROR。
- 时间戳用 civil_from_days 精确历法 + UTC+8（修复过日期漂移 bug）。
- 超 5MB 轮转归档为 `app-<时间戳>.log`（不清空、不丢历史），保留期 3 天统一清理。
- 运行监控：`install_panic_hook` 崩溃落盘；`==== APP START/EXIT ====` 启停标记；`[MONITOR]` 心跳输出运行时长、周期内 ERROR/WARN/SLOW 计数、日志文件大小。

### 2.4 相册管理（核心 CRUD）

| 项 | 说明 |
|----|------|
| 功能内容 | 创建/详情/改名/改简介/标签；批量移动到文件夹、批量设地点、批量打标签；合并相册（物理移动照片）；删除（单/批，仅删记录）；文件夹间移动；手动排序；搜索 |
| 工作范围 | `AlbumList.vue`、`AlbumDetail.vue`、`AlbumCard.vue`、`ImportErrorsDialog.vue` ←→ `album.rs`、`db/mod.rs` |
| 前端原理 | Pinia `album` store 缓存列表；卡片网格展示封面/统计；操作后局部刷新；批量导入时监听 `import-progress` 事件显示进度 |
| 后端原理 | 见下分项 |

**统计回填（`fill_album_stats`，性能关键路径）**：
1. 读 `album_stats` 缓存表；
2. 递归统计相册目录文件数（轻量 walkdir，只数不读）；
3. 文件数一致 → 目录未变，直接用 SQL 缓存统计与持久化封面，**零 IO 返回**；
4. 不一致 → 仅此相册全量重扫（单次 walkdir 完成数量/大小/首图统计），无封面时用首图生成 256px WebP 封面并写回 `albums.cover_path`，拍摄时间从首图 EXIF 读取（三级 EXIF 兜底 + mtime 兜底）。

**性能设计（2026-09 优化）**：`get_albums/get_album/list_album_photos/merge_albums/delete_photo_files/delete_photos_to_trash/move_photos_to_album` 均为 `async` 命令 + `spawn_blocking`（Tauri 同步命令跑主线程，重 IO 会卡死全部 UI）；`merge_albums` 拆四阶段——短锁读信息 → 无锁物理移动文件（同卷 rename、跨卷 copy+remove、重名自动加序号）→ 短锁删记录 + 事务写 `album_merged_sources` 来源历史 → 无锁清缩略图，全程不抱数据库锁。

**批量导入（`import_albums`）**：选中父目录 → 逐个子文件夹建相册，每步 emit `import-progress` 事件；路径全局 UNIQUE，被其他用户占用时返回 `skipped_conflicts` 明细而非报错。

### 2.6 照片网格浏览与缩略图体系

| 项 | 说明 |
|----|------|
| 功能内容 | 相册照片网格浏览（无需先入库）、缩略图懒加载、批量预热、灯箱大图查看 |
| 工作范围 | `PhotoGrid.vue`、`PhotoLightbox.vue`、`AlbumDetail.vue` ←→ `photos.rs`（`list_album_photos/get_photo_thumbs/prewarm_thumbs`）、`thumbnail.rs` |
| 前端原理 | ① `list_album_photos` 拿全量路径（walkdir 结果，轻量）；② 网格滚动时按视口批量 `get_photo_thumbs` 懒加载缩略图；③ 图片经 Tauri **asset 协议**直接从磁盘加载（绕过 base64 IPC，大幅省内存）；④ 灯箱按需加载原图 |
| 后端原理 | **三层防重复生成**：① `photo_thumb_cache` 表按 `photo_hash`（路径+大小+mtime_ns 的 FNV-1a 64，确定性哈希——修复过 `DefaultHasher` 随机种子导致重编译缓存全失效的 bug）短锁查表，命中且文件存活 → 0 IO 返回；② 表未命中查文件系统指纹命名缓存（`thumbs/grid/album_<id>_photo_<指纹>.jpg`），命中只补表不重解码；③ 都没有才生成。**生成**：JPEG 走 DCT 降采样快速路径（jpeg-decoder `scale` API，只解码所需 DCT 块，比全尺寸解码快 16~64 倍），异常图降级全尺寸解码；输出 256px。**并行**：批量未命中项按 CPU 核数分块（≤8 线程）并行生成，小批量自动串行。**写表**：生成后短锁批量 upsert，下次 0 IO 命中。链路全程"短锁查表 → 无锁生成 → 短锁写表" |

### 2.9 内容扫描与语义搜索（AI 检索核心）

| 项 | 说明 |
|----|------|
| 功能内容 | 自然语言搜照片（"海边的日落"）、以图搜图式相似检索、全文关键词检索、智能搜索（多路融合） |
| 工作范围 | `SmartSearch.vue`、`ContentSearch.vue`、`SmartAlbum.vue` ←→ `content.rs`、`db/content.rs`、`db/embedding.rs`、`textdesc.rs` |
| 前端原理 | 搜索框输入自然语言 → invoke → 结果网格展示（带 matchScore 匹配分显示，`utils/matchScore.ts`） |
| 后端原理 | **向量管道**：照片入库时生成文本描述（`textdesc.rs`：场景/人物/时间段等字段拼接，含停用词清洗）→ 调 Python sidecar CLIP 服务把描述编码为向量存 `embedding` 表；搜索时把查询文本同样编码，余弦相似度排序（`rank_by_cosine_threshold_and_limit`）。**关键词管道**：SQLite FTS5 全文索引（自愈机制：写入时检测 FTS 与主表失步，自动 repair 重建）。**融合**：`semantic_recall` + FTS 命中做 RRF（Reciprocal Rank Fusion）融合排序；三路模式（描述向量 + 关键词 + 主向量）再 fuse。**服务管理**：`warmup_semantic_service` 预热 CLIP 服务；Python 侧车由 `studio.rs` 统一管理生命周期（挑空闲端口 → 拉起进程 → 探活 → 收集输出尾部用于诊断） |

### 2.10 创意工坊

| 项 | 说明 |
|----|------|
| 功能内容 | 对照片做 AI 图像处理（风格化/增强等模型效果），产物保存为新文件；支持**叠加处理**——处理结果可一键「以结果继续」转正为新底图，重选蒙版后叠加下一个算子（如 蒙版均衡化 → 选区模糊 → 整图优化），状态栏展示完整叠加链，随时可「回到原图」重来 |

| 前端原理 | 独立 Tauri 窗口（`WebviewWindowBuilder` 按需创建），日志窗口轮询 `tail_dev_log` 增量拉取（按 offset 续读，文件轮转时前端收到 reset 协议清屏重读） |
| 后端原理 | `dev_db_sql` 仅放行 SELECT 类语句防误写；`dev_reveal_path` 调系统资源管理器并选中文件；日志 tail 按字节 offset 增量 + 单次 max_bytes 封顶分帧 |

## 三、横切设计要点

### 3.1 多用户隔离
所有数据表带 `user_id`，命令层经 `require_user` 取当前用户后传入数据层；相册路径全局 UNIQUE（跨用户占用检测）；会话 token 单用户单活。

### 3.2 并发与性能约定（本 session 优化落地）
1. 重 IO 命令一律 `async fn` + `tauri::async_runtime::spawn_blocking`（Tauri 同步命令阻塞主线程）。
2. 数据库锁只包纯 SQL，`fs::metadata`/walkdir/文件删除等 IO 一律在锁外。
3. 缩略图：表缓存（photo_hash 幂等）→ 磁盘指纹缓存 → 按需生成（JPEG DCT 降采样 + 多线程并行），杜绝重复解码。
4. 批量查询拒绝 N+1（如 `count_scanned_by_prefix` 一次全量路径查询 + Rust 前缀匹配）。

### 3.3 健壮性
- panic 钩子落盘、慢调用标记、MONITOR 健康心跳（§1.5）。
- FTS 索引失步自愈；扫描幂等（photo_hash 去重）；删除/合并操作"失败项保留可重试"。
- 缓存三层兜底：表记录丢失 → 文件指纹兜底 → 现场生成自愈。

- 缩略图缓存与原文件生命周期绑定：删除/移动照片前先清缓存（指纹依赖原文件存在）；删相册级联清全部缓存文件。
