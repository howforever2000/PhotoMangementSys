# FEAT-141 · 语义索引（CLIP）进入加速分配表

> **状态**：`done`（2026-11-03）
> **触发**：用户看到性能设置截图后指出「没有显示语义模型 CLIP 使用什么硬件」

---

## 一、问题比「没显示」更深

CLIP 明明是个 719MB 的模型，但它既不在勾选里、也不在对照表里。实际设备取决于一个
**隐式状态**：

- `set_accel()`（点过加速开关）会把 `_providers_sel` 复位成自动探测 → CLIP 落到 DirectML；
- 从没点过（默认 auto）→ `_providers_sel` 仍是开机时的「强制 CPU」→ CLIP 在 CPU。

也就是说：**同一台机器、同一个设置，CLIP 跑在哪取决于用户有没有点过那个开关**，
而界面两处都没写。这是典型的「配置无法解释运行时」。

## 二、改法：把 `clip` 变成一个可分配项

| 层 | 改动 |
|---|---|
| `config.CHANNEL_KEYS` | 追加 `"clip"`（**伪通道**：同时管 `clip_vision` / `clip_text` 双塔） |
| `ModelRegistry._channels()` | 新增：持久化文件里缺项（如老文件没有 `clip`）→ 按推荐值补齐，不再静默回落到「旧的全局 provider」 |
| `ModelRegistry._clip_providers()` | 按分配表执行：`CPU` → CPU；`GPU`/`NPU` → DirectML（**NPU 不接管 CLIP**：双塔是可变 batch 整图，不在 `OV_SHAPES` 静态化名单里）；未分配 → 旧的全局语义 |
| `default_channels()` | `clip` 的**推荐值是 CPU**（理由见下） |
| `accel_info().effective` | `clip` 映射到 `clip_vision` 会话，所以表里显示的是 ORT 实际绑定 |
| UI | 对照表新增一行「语义索引（CLIP）· 新照片」，右侧设备是**可点按钮**，单独切 CPU / 核显 |

勾选语义保持不变（FEAT-140）：NPU / 核显两个勾选管 4 条识别通道；CLIP 有自己的行内开关。
唯一例外：**只勾核显 = 「全在核显上」**，此时 CLIP 也一起给核显（用户显式选择优先）。

## 三、为什么默认给 CPU（量出来的，不是猜的）

`.pi/clip_device_probe.py`，两轮各 200 张全新建档，其余条件完全相同（NPU 三通道 + 核显
人脸检测，AI 腿 ∥ 语义腿并发）：

| CLIP 在 | 语义腿 | AI 腿 | 合计 |
|---|---|---|---|
| CPU | 58.0s / 33.3s | **17.5s / 17.1s** | 290.0 / 166.5 ms/张 |
| 核显 | **31.8s / 24.1s** | 29.9s / 22.3s | **158.8 / 120.7 ms/张** |

两件事同时成立：

1. CLIP 在核显上**自己快 1.4~1.8×**；
2. 但它整批编码会**长时间占住 DirectML 队列**（一次前向数百毫秒），人脸检测在后面
   排队 → **AI 腿被拖慢 30~70%**。

净效果取决于「这次有多少新照片」：

- **首次导入大相册**（全是新图）：语义腿是关键路径 → 核显划算（−27%~−45%）；
- **日常增量重扫**（少量新图）：语义腿几乎没活，AI 腿白白被拖慢 → 纯亏。

后者才是常态，所以默认 CPU；需要时点一下那一行即可切到核显（切完 /health 会话表会显示
`DmlExecutionProvider`，不是配置回显）。

## 四、验收（`.pi/smoke_feat141.py`）

```
[1] 旧文件（只有 4 个通道、没有 clip）→ 归一化 clip=CPU，不再静默回落
[2] 默认 clip 会话 = CPUExecutionProvider
[3] 点右侧改核显 → 会话 = DmlExecutionProvider，/accel.effective.clip = GPU
[4] 切回 CPU → 会话 = CPUExecutionProvider
```

另：FEAT-140 的四种勾选组合回归通过；`vue-tsc` 0 error；`vite build` 通过。

## 五、残留

| # | 项 | 说明 |
|---|---|---|
| R1 | CLIP 上核显的「好/坏」取决于新照片占比 | 没有自动判断（会在扫描中反复切设备、代价更大）；交给用户按「这次是首次导入还是增量」自己决定 |
| R2 | 同一把 `_GPU_RUN_LOCK` 让 CLIP 与人脸检测互斥 | 这是 DML 会话跨线程并发不安全的既有约束（BUG-2026-0923-001），不是本次引入 |
| R3 | 语义索引没有独立勾选框 | 保持「两个勾选 + 一行可点的设备」而不是变成三个开关 |
