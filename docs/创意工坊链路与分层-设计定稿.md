# 创意工坊链路与分层 · 设计定稿

- 日期：2026-11-14（初版）；2026-11-17 修订定位判据
- 状态：已确认，执行中
- 适用范围：创意工坊（`/workshop/workbench`）图像出片链路与分层
- 配套判据：[workshop-positioning.md](../.dsh/knowledge/workshop-positioning.md)

## 一、定位基准

- **工位**：LR 导出 JPEG 之后的快速出图站；懒人快速出图，不做精修。依据：`.dsh/knowledge/workshop-positioning.md`「定位」段，2026-11-14 用户裁定。
- **硬指标（2026-11-17 修订）**：**主路径**导入到出图 ≤3 次点击、默认不出现调参面板；**可选支线**允许「先出样片（抽样 ≤5 张）→ 微调配方级少量参数 → 确认后套全局」。依据：同上「修订记录」，用户裁定把「零调参」放宽为「主路径零调参 + 可选样片微调」。
- **微调边界（三条硬约束）**：只暴露配方级少数几个量（瘦脸/大眼/磨皮/保留质感/调色力度）；必须基于样片而非全量；面板默认收起。依据：同上「修订记录」。
- **职责切分**：精修归 LR/PS，本工坊只接 LR 导出后的那一步。依据：同上「边界」。
- **不做项**（完整理由与归属见判据文件，此处不整段抄）：RAW 解码、16bit 线性工作流与色彩管理、局部调整（画笔／径向／蒙版）、曲线调参、手动液化笔刷、精修级人像控制。依据：同上「不做清单」。
- 结论：分层设计必须让「主路径 ≤3 次点击、默认零调参面板」成立；微调支线不得改变主路径的点击数与默认观感。依据：定位先于架构。

## 二、五层抽象与取舍

| 层 | 结论 | 依据 |
| --- | --- | --- |
| L0 定位落库 | 把用户裁定固化为 `.dsh/knowledge/workshop-positioning.md` 硬判据，作为后续各层的准入条件 | 决策此前只在对话中、全仓未落库，制品层措辞已漂移（E1／E2） |
| L1 `op_catalog.json` 单一真相源 | 算子 id / params / requires / requiresBefore 只在此定义；前端 Vite 构建期内联、Rust cargo parity、Python spec `json.load` 三端同源 | 现有注册是 `Record<string,string>` 弱类型（E1） |
| L2 `recipes.json` 配方 | A 人工选配方与 B 大模型产出**同构**，统一落成同一 Recipe / `steps[]` 结构 | 后端已产出 plan/steps 但前端零引用，需统一载体（E2） |
| L3 `execute_plan` 加 `on_step` 与显式依赖 | 执行器逐 step 发 `on_step` 回调，依赖由 `dependsOn` 显式声明，取代隐式顺序 | 现有 `_ORDER` 隐式排序且 `verify_result` fail-open（E3） |
| L4 `meta.plans` 与结构化 `steps[]` 接前端只读展示 | 前端只读渲染 steps 状态与结果图，不承载编排 | 前端 12 分支硬编码、无事件出口（E1／E2） |

**明确不做**（本期边界，不是延后）：

| 不做项 | 依据 |
| --- | --- |
| DAG 画布 | 定位禁止调参式交互，画布必然引入节点编辑与多次点击 |
| Artifact LRU | 一期配方只读、4 条固定，无多版本产物淘汰需求 |
| 幂等缓存 | 全量收敛优先；未建立稳定 op/params 指纹前做缓存会固化 fail-open 的错误结果（E3） |
| replan 回灌 | B 路径产出同构即可，一期不做执行后重规划闭环 |
| 视觉 LLM critic | Q4 已锁定本地零模型客观指标 critic，不引入视觉模型与额外推理成本 |

## 四、决策锁定

| 决策号 | 锁定结论 | 依据 |
| --- | --- | --- |
| Q1 | `op_catalog.json` 单源 + Vite 构建期内联 + cargo parity + spec `json.load` | E1 无契约、E3 后端已有白名单，需三端同源而非各写一份 |
| Q2 | 保留 `/workshop/workbench` 独立路由，但共用 `RecipePicker` 与执行器 | 不改 IA 现状可避免入口合并回归；共用消除重复实现（Q5 全量收敛） |
| Q5 | 接受全量收敛 | 决策未落库 + 措辞漂移 + E1／E2／E5／E6 同类问题散布，分批收敛会留下两套口径 |
| Q3 | 4 条配方（自然／通透／胶片／人像）一期只读 | 「≤3 次点击、零调参面板」下，只读配方即可覆盖一键出片（第六节①） |
| Q4 | 默认开本地零模型客观指标 critic（过曝／噪声／锐度／肤色） | 本地零模型、无额外推理成本，替代视觉 LLM critic（第二节明确不做） |

## 五、数据结构样例

**OpSpec**（`op_catalog.json` 单条）：

```json
{
  "id": "face_reshape",
  "params": {
    "slim": { "min": 0, "max": 100, "default": 30, "step": 1 },
    "eyes": { "min": 0, "max": 100, "default": 20, "step": 1 }
  },
  "requires": { "models": ["face_landmark_68"] },
  "requiresBefore": ["auto_grade", "lut_apply"]
}
```

**Recipe**（`recipes.json` 单条，portrait，5 步，末步 optional）：

```json
{
  "id": "portrait",
  "label": "人像",
  "steps": [
    { "op": "auto_grade" },
    { "op": "local_film" },
    { "op": "face_reshape" },
    { "op": "skin_smooth" },
    { "op": "local_upscale", "optional": true }
  ]
}
```

**RunStep**（前端只读展示类型，对应 L3 `on_step` 与 L4 `steps[]`）：

```ts
export interface RunStep {
  index: number;                 // 执行序号，on_step 回调定位用
  op: string;                    // 算子 id
  dependsOn: number[];           // 显式依赖的 step index（L3）
  optional: boolean;             // 失败可跳过，不阻断出片
  status: 'pending' | 'running' | 'done' | 'skipped' | 'failed';
  output?: string;               // 结果图路径，只读展示
}
```

- **命名空间说明**：算子 id 与工具 id 分属 `OPS` / `REGISTRY` 两个命名空间，同名不是冲突。依据：L1 定义算子契约、L2 组合工具步骤，二者各自独立命名并按 id 映射。

## 八、不做清单（边界）

| 不做项 | 边界依据 |
| --- | --- |
| RAW 解码 | LR 职责；本工坊从 LR 导出 JPEG 起步 |
| 16bit 线性工作流与色彩管理 | 现有算子全在 8bit sRGB，`lutcube.py` 按 255 量化 |
| 局部调整（画笔／径向／蒙版） | 精修交互，必然引入调参面板 |
| 曲线调参 | 精修调参，违反「零调参面板」 |
| 手动液化笔刷 | 精修级手动控制，与 ≤3 次点击冲突 |
| 精修级人像控制 | 只保留一键级人像配方（第五节 portrait） |
| DAG 画布／Artifact LRU／幂等缓存／replan 回灌／视觉 LLM critic | 第二节「明确不做」逐条给出依据 |
