# 缩略图 / 派生缓存

> 缩略图是本项目最容易「静默失效」的一层：缓存键、命名、存活性、并发任何一处出错都会表现为「空白 / 卡死 / 全量重建」。均来自 `bug-notes.json`。

## 持久化缓存命名禁止用 DefaultHasher

- **触发条件**：用 `std::hash::DefaultHasher` 生成缓存指纹、文件名或 URL。
- **先做**：改用确定性哈希（FNV-1a 64 / xxhash / CRC32）；缓存文件名格式变更时提供旧文件复用 / 重命名路径。
- **为什么**：`DefaultHasher::new()` 的种子在每次编译时随机生成，跨编译不稳定 → 重编译后同一文件的指纹全变 → 缓存全部失效。
- **违规症状**：重编译后 `get_albums` 卡死 140 秒；缩略图全量重建（大图场景被放大成可用性问题）。
- **来源**：`bug-notes.json` BUG-2026-0815-001（`src-tauri/src/thumbnail.rs`）。
- **记录日期**：2026-11-12

## 缓存命名变更必须同时改生成端与查询端

- **触发条件**：改缓存文件名格式（如引入 WebP 嵌套命名 `grid_thumb_cache_name` 而生成端仍是 flat `album_{id}_photo_{fp}.jpg`）。
- **先做**：生成端与查询端统一走同一命名函数；旧格式提供迁移 / 复用 / 清理策略。
- **为什么**：两套命名并存 → 查询永远落空，多一次无效 `stat`，缓存可能双份占盘。
- **违规症状**：`thumb_hit` 永远为 0。
- **来源**：`bug-notes.json` BUG-2026-0916-002（open）。
- **记录日期**：2026-11-12

## 缓存键 = 契约：「身份」与「产物」版本要分离

- **触发条件**：给缓存键掺入渲染版本 / 算法版本（如 EXIF 转正把 v2 掺进表主键 `thumb_photo_hash` 与文件名 `file_fingerprint`）。
- **先做**：身份键（哪张照片 `photo_hash`）必须与扫描侧 / 其它表同源；产物版本只进产物名（文件名），不进身份键；**bump 缓存版本必须同时交付迁移路径**。
- **为什么**：v2 同时换了「表主键」与「文件名」两把钥匙且无迁移 → 全库 2.5 万张一次性失效；同时扫描侧 `photo_content_scan.photo_hash`（未掺版本）LEFT JOIN 仍对上旧行、判定「缺图 0」，懒加载侧用新键又一条查不到。
- **违规症状**：升级后全量重生成；「一次生成永久保存」被打破；缓存静默清零（27,984 行表 + 35,707 个文件变不可达）。
- **来源**：`bug-notes.json` BUG-2026-1023-010、BUG-2026-1023-009。
- **记录日期**：2026-11-12

## 复用旧缓存要覆盖所有历史代次

- **触发条件**：重构 `reuse_legacy_thumb` 等兼容代码。
- **先做**：候选列表遍历**所有**历史命名代次（grid 指纹命名 → 封面指纹命名 → 最早一代按源图文件名 `album_<id>_<safe_stem>.jpg`），命中即整字节复制（不转码）；函数文档写着的复用承诺要和实现一起评审。
- **为什么**：0f1e1ff（WebP 改造）只保留了指纹命名的两代，漏掉最早按文件名的代次 → 从更老版本直升的用户全量重新解码。
- **违规症状**：老用户升级后首次打开相册全量重新解码生成；单测先红被当「测试过期」把真回归一起埋掉。
- **来源**：`bug-notes.json` BUG-2026-0918-003（`src-tauri/src/thumbnail.rs`）。
- **记录日期**：2026-11-12

## 缓存表里的路径下发前必须校验存活

- **触发条件**：`LEFT JOIN photo_thumb_cache` 取 `thumb_path` 直接塞进响应式表渲染 `<img src=...>`。
- **先做**：返回前逐条 `is_file()` 校验，死链置 `None`（每页 ≤300 次 stat，实测 <2ms）；前端 `<img @error>` 兜底 `markThumbBroken`；兜底条件不要只写 `== null`，还有第三态「有值但无效」。
- **为什么**：缓存表的「行在」≠「文件在」；把缓存当事实用，文件被清掉后长期显示空白，日志一片 OK。
- **违规症状**：时间线缩略图大量空白（实测 24,917 行里 53.3% 的 thumb_path 指向已被清掉的文件）。
- **来源**：`bug-notes.json` BUG-2026-1028-014。
- **记录日期**：2026-11-12

## bump 缓存键 = 全库冷启动压测

- **触发条件**：改「影响像素」的渲染逻辑并同时 bump 缓存键（升级后全库缓存一次性失效）。
- **先做**：按「冷启动压测」评估并发路径；任何「按相册分组 → `Promise.all`」的批量请求先算 **分组数 × 每组片数 × 后端每请求线程数**。
- **为什么**：时间线 `loadThumbs()` 按相册分组一次性要全量 → 129 路并发 × 后端每路 `thread::scope` 开 8 线程 ≈ 1000 线程同时解码大 JPEG → 资源打穿。
- **违规症状**：`0xC00000FD`（名字叫栈溢出，实际是资源耗尽）；进程直接退出；线程数峰值 732 / 私有内存 1.2GB。
- **来源**：`bug-notes.json` BUG-2026-1023-009（`src-tauri/src/thumbnail.rs`、`src/utils/thumbQueue.ts`、`src/views/Timeline.vue`）。
- **记录日期**：2026-11-12
