# UI 对比度 / 设计令牌

> 主题系统与设计令牌层的对比度纪律。均来自 `bug-notes.json`。

## 文字色必须感知「实际合成背景色」，页面背景与卡片底色是两个语境

- **触发条件**：主题文字色只跟浅 / 深模式走（`isDark ? '#f5f7ff' : '#1f2733'`），与背景色 / 渐变 / 背景图无关。
- **先做**：两层模型 —— `textColor` 跟随模式（卡片语境）；新增 `onBgColor/onBgSubColor` 只对**实际页面背景**算对比度（WCAG，不足 4.5:1 自动翻转），经 body 变量 `--color-on-bg(-2)` 下发，各页直接落在背景上的标题逐个切换。
- **为什么**：卡片底色由模式决定，若 `--color-text` 整体跟「页面背景」翻转 → 深色模式卡片文字被翻成深色、失去对比、不可读。
- **违规症状**：文字与背景融为一体；卡片内文字被错误翻深色。
- **来源**：`bug-notes.json` BUG-2026-0919-002、BUG-2026-0919-004（`src/stores/theme.ts`）。
- **记录日期**：2026-11-12

## 新增文字令牌按「预设渐变最亮/最暗端点」标定，不是纯黑/纯白

- **触发条件**：设计令牌直接取自效果图的透明度（46% / 26%）。
- **先做**：`rgba` 透明度必须叠在具体底色上算合成色再比；标定基准取**预设三段渐变的最亮 / 最暗端点**；「弱化」靠字号与字重建立，颜色只保证可读下限。
- **为什么**：透明度本身没有对比度，同一 alpha 在深底与浅底结果完全不同（26% 白在 `#0a090d` 上 2.09:1、26% 黑在 `#faf8f5` 上 1.95:1）；页面底实际是预设渐变，比纯黑亮得多。
- **违规症状**：fg-3 深 2.09:1 / 浅 1.95:1，全部不达标；「弱化」值踩穿对比度（2.83 vs 4.5）。
- **来源**：`bug-notes.json` BUG-2026-1023-003、BUG-2026-1024-007（`src/assets/tokens.css`）。
- **记录日期**：2026-11-12

## 对比度审计工具先自检假阳性

- **触发条件**：审计工具报大量「不合格」。
- **先做**：底用**元素自身背景**而非页面渐变；正确解析 Chromium 的 `color(srgb 0~1 / a)`（不是 0~255）；豁免禁用态；如果一半「不合格」是按钮/禁用态，那是工具的问题。
- **为什么**：假阳性比没有工具更糟 —— 它会把真实缺陷埋掉。
- **违规症状**：审计假阳性占六成。
- **来源**：`bug-notes.json` BUG-2026-1024-004。
- **记录日期**：2026-11-12

## 深色主题全局 `.btn` 覆盖要排除实心/幽灵变体，禁用态用实心灰不用整体 opacity

- **触发条件**：深色模式按钮「太透明看不清」。
- **先做**：`body.theme-dark .btn` 增加 `:not(.btn-primary/.btn-danger/.gs-btn-primary/.gs-btn-danger/.btn-ghost)` 排除；幽灵按钮改浅蓝实底；禁用态统一改实心灰（不再用整体 `opacity`）。
- **为什么**：全局规则特异性高于组件实心按钮规则，把主色刷成半透明白；`btn-ghost` 透明底 + 1px 描边在白底面板等于没底；禁用态整体降透明度。
- **违规症状**：主色按钮变透明；白底白钮；禁用态整体发虚（用户描述为「太透明」）。
- **来源**：`bug-notes.json` BUG-2026-0925-002（`src/assets/main.css`、`GlobalScanPanel.vue`、`ModelGpuSettings.vue`）。
- **记录日期**：2026-11-12
